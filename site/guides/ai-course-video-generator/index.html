从一个主题到课程视频，中间不是只差一段脚本。

一条可发布的课程视频还需要事实边界、章节结构、旁白时长、画面布局、字幕、配音、横竖双版和最终 QA。任何一个环节漂移，都会让“生成成功”变成不能交付。

目标观众

他们已经知道什么、最需要解决什么、能接受多深的技术细节。面向初学者和面向专业团队的脚本结构完全不同。

核心结论

视频结束时希望观众记住哪一件事。没有明确结论，章节很容易变成相关信息的堆叠。

事实与来源

医学、法律、金融和版本敏感软件内容必须由用户提供或确认可靠事实，Agent 不能凭看似合理的语言补齐权威结论。

风格与节奏

语气、视觉密度、旁白速度、视频时长和平台比例需要在渲染前确定，不能等成片后再用裁切修补。

LectureCast 的完整生产链

  1. 商业 onboarding：Agent 验证通用 API Key、有效月卡、共享 credits 与本地渲染器。
  2. 稳定选择与 Brief：用户确认受众、重点、风格和素材边界，不在这一步扣 credits。
  3. 签名 ProductionManifest：用户明确批准 10 credits 后，Director 返回不可变计划和完整签名讲稿。
  4. 完整讲稿审阅：用户逐段查看旁白并再次批准，宿主 Agent 不得自行改写签名内容。
  5. 本地 TTS 与实测时长：使用 Edge TTS 或用户自己的 MiniMax Key 生成旁白，实际音频时长驱动画面和字幕。
  6. 双版渲染：Remotion 分别生成 B 站 1920×1080 横版和小红书 1080×1920 竖版，不是把一个画面简单裁成两种容器。
  7. 字幕、封面与 QA：ffmpeg 烧录中文字幕，生成两张 PNG 封面，并检查解码、音频覆盖、字幕字形、尺寸和完整渲染。
标准交付是四个文件。两条 MP4 成片和两张对应封面。任何访问、素材、时长、字幕或渲染检查失败，都应停止交付，而不是用一段“完成了”的文字代替文件。

三次独立人工门禁，分别保护什么

门禁用户确认什么不确认会怎样
Creative Brief主题方向、目标观众、事实与视觉选择不进入付费生成
10-credit Manifest同意按当前任务生成一次签名 ProductionManifest不扣 credits，不生成签名计划
完整签名讲稿逐段确认最终旁白文本不进入 TTS、字幕与渲染

这些门禁不是重复弹窗。它们分别保护创意方向、付费动作和对外表达，任何一项都不能由宿主 Agent 代替用户假设同意。

常见问题

LectureCast 是否会自动开始付费生成？

不会。用户先批准 Brief，再明确批准一次 10-credit Manifest，最后审阅完整签名讲稿，之后才进入本地执行。

原始媒体和成片会上传吗？

不会。原始媒体、音频、字幕、渲染和成片留在本机；旁白文本会发送给所选 TTS 服务。

支持哪些系统？

当前支持 macOS 和 Windows 原生环境；Linux 与 WSL 不在支持范围内。
